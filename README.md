# Лабораторная работа №1: вариант №11 (R1)

Задача — диффузия с поглощением. Этапы 8.1–8.5 выполнены отдельными скриптами. Результаты собраны в [отчёте](lab1_R1_report.md); его версия для печати — [PDF](lab1_R1_report.pdf). Постановка и критерии взяты из раздела 9 методички «Лабораторная работа 1».

## Запуск

Нужны Python 3, NumPy, SciPy и Matplotlib. Из этой папки:

```bash
python3 lab1_stage_8_1_R1.py
python3 lab1_stage_8_2_R1.py
python3 lab1_stage_8_3_R1.py
python3 lab1_stage_8_4_R1.py
python3 lab1_stage_8_5_R1.py
```

Порядок важен: более поздние этапы используют сохранённые решения предыдущих. Параметры конкретного скрипта выводятся через `python3 имя_скрипта.py --help`. Пятый этап повторно создаёт Markdown-отчёт; PDF после повторного запуска нужно собрать заново.

## Пункт 9.1: требования к программе

1. Разделять постановку задачи, сборку матрицы, решатели, предобуславливатели, обработку результатов и построение графиков.
2. Хранить рабочую матрицу в разреженном формате; не вычислять явно обратные матрицы `A⁻¹` и `P⁻¹`.
3. Принимать вариант, размер сетки, порог относительной невязки и параметры метода без изменения текста функций решателей.
4. Сохранять сводные числовые результаты в CSV и автоматически строить обязательные графики.
5. Проверять достижение критерия остановки и корректно обрабатывать превышение максимального числа итераций.

**Состояние проекта.** Разреженное хранение, самостоятельные решатели, обработка результатов, CSV, графики и проверка сходимости есть. Часть параметров задаётся ключами командной строки (`--tol`, `--max-iter`, `--nx`, `--ny`, `--grids`), но программа в целом рассчитана только на R1: выбор произвольного варианта и единый интерфейс для произвольного `N` пока не реализованы. Поэтому требование 9.1(3) выполнено не полностью. Разделение на компоненты сделано частично: код распределён по этапам, общего интерфейса запуска всей лабораторной нет.

## Пункт 9.2: требования к отчёту

Отчёт должен быть самодостаточным для выполненного варианта и содержать:

1. Краткое описание реализованных методов и критерия остановки без переписывания справочного раздела.
2. Результаты и проверки корректности **всех пяти** этапов.
3. Сводные таблицы, обязательные графики и поле решения.
4. Сопоставление невязки и погрешности решения СЛАУ на тестовой системе с известным решением.
5. Сравнение с независимым решателем.
6. Физическую интерпретацию результата и выводы о сходимости методов.
7. Инструкцию запуска и полный исходный код либо ссылку на него.

В таблицах должны стоять **заданный порог** и **достигнутая относительная невязка**. Снимки экрана программного кода не принимаются. Текущий [отчёт](lab1_R1_report.md) включает эти материалы; исходный код дан ссылками на файлы проекта.

## Пункт 9.3: защита

На защите нужно объяснить структуру матрицы, условия применимости методов, разницу между невязкой и погрешностью и смысл результатов. Преподаватель назначает индивидуальную модификацию. **До запуска** студент формулирует ожидаемый эффект, **после расчёта** сравнивает прогноз с результатом. Возможные изменения: контраст коэффициента `a`, положение источника при сохранении интегральной интенсивности, порог `ε_res`, число узлов по одной координате, параметр ПВР или SSOR, поглощение `c`, порядок нумерации узлов, матрично-свободный оператор вместо CSR или начальное приближение. Эта часть выполняется при назначении модификации преподавателем.
